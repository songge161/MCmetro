# 首个真实街区方块样板

目标：将实际 OSM 街区生成到可导入游戏的建筑文件，供 Windows 创造模式探索验收。
本阶段运行于 Mac，本地处理，不需要在线模型或地图服务器。

## 已生成的样板

- 配置：`data/regions/ikebukuro_pilot.yaml`，Sunshine 60 通西段。
- 输入：`data/processed/ikebukuro_east/`，来自 BBBike Tokyo 原始 PBF。
- 输入 GeoJSON SHA256：`31346929a1c750154b149f98f3a7f5cda768706701b288c5705c4ab5322dd90f`。
- 尺寸：181×44×156（X、Y、Z），局部近似 1 米/格，未压缩。
- 当前产物：`out/ikebukuro_pilot_v5/`；原 `out/ikebukuro_pilot/` 基线保留。
- 38 栋建筑；29 栋多层，9 栋简化为单层；共 149 个开放楼层。
- 26 栋使用双宽楼梯，3 栋使用单宽楼梯；相比基线恢复 3 栋上层、增加 10 个开放楼层。
- 40 个地面道路线对象，不代表 40 条不同命名街道；宽度均为类型规则推定。
- 地面 Y=1、入口脚底 Y=2；每层 5 格，最多 8 层；入口不包含门扇。
- 20 栋使用缺失楼层默认值，18 栋有 `building:levels`；精确差异记录于生成报告。

当前样板不包含完整池袋站和 Sunshine City 地标建筑，不能据此验收地标还原。
9 栋单层简化也是已知缺口，现有直跑模板仍放不下，需要后续研究转折楼梯，不能当作最终楼高。

## 处理顺序

1. 检查生成范围在快照覆盖范围内，建立西北角原点，X 向东、Z 向南。
2. 将地面道路和完整建筑轮廓栅格化，保留多边形内洞。
3. 过滤地下、高架及暂不支持的道路类型，避免把不同高程错误合并。
4. 建筑优先保留轮廓；推定道路铺装与轮廓冲突的单元不覆盖建筑并记录数量。
5. 在建筑外部从道路计算步行连接，选择可连接室内的边界单元开门洞。
6. 优先两格宽直跑楼梯，其次单宽（7×5 或 7×4 内部空间）模板；生成楼板、洞口、护栏和照明。
7. 对入口至每层所有可站立开放单元做两格净空、一步高度的连通性检查。
8. 校验通过后导出确定性的 Sponge v2 NBT，并打包来源报告、预览和导入说明。

楼梯候选未通过检查时尝试下一位置，全部失败才降为单层并清除候选残留。
报告记录 `stair_template`、`stair_width`、候选次数和 `floor_downgrade_reason`。
入口附近最多七格范围内生成橱窗和饰带，始终位于建筑轮廓内，不向道路突出；
明确标为住宅的建筑保留普通窗户。门面规则不推断真实商户名称、品牌或经营用途。
`验收清单.md` 列出所有建筑入口相对坐标、计划/生成楼层及简化原因，游戏内结果全部待测。

连通性是离线近似检查：楼梯按整格支撑近似，护栏不可作为可站立支撑。
Minecraft 的精确碰撞盒、方块邻接更新和玩家实际行走需要游戏内验证。
任何建筑未通过检查都会中止导出，不能把绿色状态当作游戏内验收。

## 导出与验证依据

目标 Java 1.20.1，DataVersion=3465。仅原版静态方块，不含实体或方块实体数据。
遵循 [Sponge v2 规范](https://github.com/SpongePowered/Schematic-Specification/blob/master/versions/schematic-2.md)：
GZip NBT、根对象 Schematic、方块调色板、X 最快变化的 BlockData。
首版最多 128 个方块状态，因此调色板索引每个占一个合法 VarInt 字节。
测试使用独立的 nbtlib 读取导出结果，而非用同一个写入器自证正确。

Windows 需支持 Java 1.20.1 的 Fabric WorldEdit；操作遵循
[WorldEdit 剪贴板文档](https://worldedit.enginehub.org/en/latest/usage/clipboard/)。
导入 `.schem` 的游戏内验证仍未完成。
